The kernel trick, step by step

Some data can’t be split by a straight line, but becomes splittable if you add the right extra dimensions. The trick is getting the answer you would have had in those dimensions without ever going there.

Step 1. Lift the data into a higher dimension

These rings can’t be separated by a line in 2D. Lift each point (x₁, x₂) to φ(x) = (x₁², √2·x₁x₂, x₂²) and a flat plane splits them. Press Lift, then drag the 3D view to rotate it.

Accuracy of the flat plane: –. In 3D the rule is a plain linear one, even though in 2D it is a circle.

Step 2. Get the same similarity without lifting

Linear methods only need dot products between points, never the lifted coordinates themselves. Drag points a and b and compare two routes to the same number.

Route A: lift first, then take the dot product

Route B: kernel shortcut, stay in 2D

Route B is the kernel k(a, b) = (a·b)². It never builds φ(a) or φ(b), yet it equals their dot product exactly.

Step 3. Why the shortcut matters

A polynomial kernel (x·z + 1)ᵈ on n inputs implicitly uses every product of up to d coordinates. Raise n and d to see how many explicit features you would have to build.

Explicit route: features to build and multiply
Kernel route: multiplications for one dot product

The RBF kernel goes further: it matches a dot product in an infinite-dimensional space, which could never be built explicitly, while each kernel evaluation stays a single cheap exponential.

So the full recipe is: pick an algorithm that only uses dot products, replace each dot product with a kernel k(x, z), and you get a nonlinear method at nearly the same price.
