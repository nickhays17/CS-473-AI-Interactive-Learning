Naive Bayes, generative and discriminative models

Three short stops: the idea, a 2D sandbox where you can watch both kinds of model learn from your points, and a spam filter you can do by hand.

Two ways to learn a classifier

You want to predict a label y (say spam or not spam) from features x. There are two routes.

Generative: learn how each class makes data

p(x, y) = p(x | y) · p(y)

Model what spam looks like and what ham looks like, then use Bayes' rule to flip it around:

p(y | x) ∝ p(x | y) · p(y)

Examples: Naive Bayes, Gaussian mixtures, hidden Markov models.

Discriminative: learn the dividing line

p(y | x)

Skip the story about how x arises. Model only the answer you need: given x, which label?

Examples: logistic regression, SVMs, most neural network classifiers.

A generative model can sample new x values because it knows p(x | y). A discriminative model cannot, but it spends all its capacity on the boundary.

Where Naive Bayes fits

Naive Bayes is a generative model with one simplifying assumption: given the class, the features are independent.

p(x | y) = p(x₁ | y) · p(x₂ | y) · … · p(x_d | y)

With d binary features, the full p(x | y) needs about 2d numbers per class. The naive version needs d. The assumption is usually false (the words "free" and "winner" often appear together), but the resulting classifier is often still good, because it only needs to get the ranking of the classes right, not the exact probabilities.
