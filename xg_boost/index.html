The settings that matter most

Open each one for what it does and how to set it on a typical biomechanics dataset (often a few hundred to a few thousand samples).

learning_ratetry 0.03–0.1

How much each tree is allowed to correct. Smaller values need more trees but generalise better.

Use a low rate, many trees, and early stopping to pick the count.

n_estimators + early_stopping_roundsset high, then stop early

Number of trees. Set it to something like 2000 and let early stopping halt training when the validation error stops improving.

Validate on held-out participants, not random rows.

max_depthtry 2–4

How many questions a tree can ask in a row. Deeper trees capture interactions, such as speed combined with body mass, but overfit quickly on small data.

min_child_weighttry 3–10

The minimum amount of data a leaf needs. Larger values stop the model from building rules around a handful of strides.

subsample and colsample_bytreetry 0.6–0.9

Each tree sees a random fraction of rows and of features. This adds diversity and helps when features are correlated, as joint angles usually are.

reg_lambda and gammaincrease if overfitting

Lambda shrinks leaf values (L2 penalty). Gamma is the minimum gain required to make a split. Both make the model more conservative.

Where biomechanics data can fool you

Split by participant, not by stridethe biggest one

Strides from the same person are highly similar. If they land in both train and test sets, the model recognises the person and your score looks great. Use GroupKFold with participant ID as the group.

Trials and sessions leak toosame logic

If you test on new participants, split by participant. If you test on a new session of known participants, split by session. Match the split to the question you want to answer.

Trees can’t extrapolatelimits of the method

A tree predicts an average of training samples, so it never predicts beyond the range it has seen. If a new participant walks faster than anyone in training, the prediction stays flat. A linear model can extend a trend; XGBoost cannot.

Features matter more than tuningwork on these first

Peak joint angle, range of motion, time of peak, stance duration, symmetry index, and participant descriptors (height, mass, speed) are usually stronger than raw time series. Time-normalise strides to 101 points if you use waveforms.

Run a simple baseline firstsanity check

Compare against a ridge regression or logistic regression. If XGBoost is only slightly better, the simpler model is often the more defensible choice.

Explain with SHAPinterpretation

Built-in feature importance can mislead when features are correlated. SHAP values show how each feature pushed each prediction, and work well for questions like “does cadence matter more than step width?”

A starting point for your data

Assumes a table with one row per stride (or trial), a target column, and a participant ID column. Rename to match yours.

import pandas as pd, numpy as np
from xgboost import XGBRegressor          # XGBClassifier for categories
from sklearn.model_selection import GroupKFold
from sklearn.metrics import mean_squared_error

df = pd.read_csv("biomech_data.csv")
y = df["peak_knee_moment"]                # your target
groups = df["participant_id"]
X = df.drop(columns=["peak_knee_moment", "participant_id"])

scores = []
for tr, te in GroupKFold(n_splits=5).split(X, y, groups):
    model = XGBRegressor(
        n_estimators=2000, learning_rate=0.05,
        max_depth=3, min_child_weight=5,
        subsample=0.8, colsample_bytree=0.8,
        reg_lambda=5, early_stopping_rounds=50,
    )
    model.fit(X.iloc[tr], y.iloc[tr],
              eval_set=[(X.iloc[te], y.iloc[te])], verbose=False)
    pred = model.predict(X.iloc[te])
    scores.append(np.sqrt(mean_squared_error(y.iloc[te], pred)))

print("RMSE per fold:", np.round(scores, 3))
print("Mean RMSE:", np.mean(scores).round(3))

# Explain it (pip install shap)
import shap
shap.plots.beeswarm(shap.Explainer(model)(X))

Note: the early-stopping set above doubles as the test fold, which is slightly optimistic. For a final number, hold out a separate group of participants.
